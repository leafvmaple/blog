# Godot の 2D パイプライン上に HD-2D を積む

HD-2D——アイソメトリックなピクセル世界に現代的なポストプロセスと動的ライティングを重ねる、Octopath Traveler / Triangle Strategy の系譜——の難所は個々のエフェクトそのものではなく、Godot 4 の gl_compatibility という 2D バックエンドの上でそれらをどう成立させるかにある。パイプライン全体の形を決めるのは二つのハードな制約だ:**CanvasLayer をまたぐ画面読み取りが、このバックエンドでは純白を返す**;そして、**どんなスプライトでもカスタムマテリアルを付けた瞬間、ライティングのかかったキャンバス上で一定して約1割暗くなる**。前者がポストプロセスの繋ぎ方を決め、後者はリムライト・シネマティックグレーディング・スプライトの明度上げの三か所で繰り返し顔を出す。

![実機の完成画面:稲香村、全エフェクト](https://code.leafvmaple.com/assets/hd2d/hero.gif)

上が実機の完成画面(稲香村、全部オン:夕暮れグレード + ビネット + 距離フォグ + 構造物/キャラクター投影 + リムライト + ブルーム + 舞う落ち葉)。以降の各節では「素のベースライン vs その技術だけを足したもの」の比較で一層ずつ分解していく——レンダリングの土台から上へ、スクリーンポストプロセス、光と影、カスタムマテリアルの癖、時刻と大気、そして最後にこの道がどこへ行けるか。

## 一、土台は SubViewport 一択

最初に思いつくのは、画面全体を覆う `ColorRect` にポストプロセスの shader を直接貼り、`screen_texture` で描画済みの世界をサンプリングするやり方だ。Forward+ では通るが、gl_compatibility では通らない——**CanvasLayer をまたぐ画面読み取りが、このバックエンドでは純白を返す**。

確実なのは、ゲーム世界全体(シーン/ワールドマップ/戦闘/タイトル)を一つの `SubViewport` に描き込み、ポストプロセスの shader はそれを収める `SubViewportContainer` 側に貼って、その実体のある viewport テクスチャをサンプリングする方法だ。HUD やモーダルは SubViewport の外に残るので、決してポストプロセスを通らず、くっきり鮮明に保たれる。

この SubViewport はついでに「任意の解像度」も解決する:**物理ウィンドウ解像度**で描画し(下限 1280×800)、同時に `size_2d_override` で 2D の**論理座標**を元の論理サイズに固定する——カメラ・ズーム・画角のコードは一切触らず、レンダリング解像度だけがウィンドウに追従して上がる。ウィンドウを広げて得られるのは、より鮮明な画であって、より広い視野ではない。コンテナはレンダリング解像度に応じて逆スケールをかけ、同じ論理レイアウト領域に貼り戻して、外へ「持ち上げた」UI と揃える。アイソメトリックなピクセルゲームはこうして当時のような固定の低解像度から抜け出せる——しかもタイルとスプライトの整列ロジックは一行も変えずに。

この層がその後、画面全体にかかるエフェクト一式を担う。すべて `hd2d_post.gdshader` の中、一度の fragment で走り切る:露出/彩度/コントラスト、暗部を寒色・ハイライトを暖色にするスプリットトーン、ブルーム、ティルトシフト、ビネット、色収差、ディザリング、フィルムグレイン、3D LUT ルックアップ、距離フォグ。値は `hd2d.json` で上書きし、書かなければエンジン既定値を使う。

この層の項目はそれぞれ別の役割を持つ:`exposure_scale` は時刻テーブルに入らない追加係数で、どの時刻でも一律に暗くする;ビネットは視線を画面中央へ寄せる;3D LUT はバラバラのカラー調整パラメータを一枚のルックアップテーブルに置き換えて画面全体のムードを色で寄せる;ブルームは明部を滲ませ;色収差は画面の縁で R/B チャンネルを1〜2ピクセルずらし;ディザリングはバンディングを消し、グレインは質感を足す。

素のベースラインにこれらを一つずつ足すと、各自の寄与はむしろはっきり見える(下図、各ペア左が素・右が追加):

![ポスト4種: ブルーム/色収差/グレイン/露出](https://code.leafvmaple.com/assets/hd2d/postfx.png)

ただし完成画面に積み重なると、どれも**穏やかな全体的微調整**だ——一つだけオンオフしても投影やリムほど一目では分からず、重ねて初めて成立する「下地の味」になる。本当に幾何的なエフェクト(投影・リム・被写界深度)が最もコントラストが強く、以降の節で扱う。

## 二、単一の光源が三種類の影を養う

影は三種類、仕組みもそれぞれ違う:**スプライトの方向影**(現フレームの暗いシアーコピー)、**構造物の投影**(壁/建物/木のタイルのシルエットを光の向きにレイマーチ)、**接触 AO**(足元に常駐する柔らかい暗がり、光の向きに依存しない)。前の二つは向きが一致していなければ一目で嘘とわかる——だから同じ光源を読む。

太陽を地面(セル)平面の上に定義する:太陽を指すセル空間ベクトル(方位角)に高度角を一つ。地面から `h` ピクセル高い点の影の変位は `cell_to_screen(anti-sun) * h * cot(elevation)` ——アイソメトリックで「影が傾いた地面に貼り付くときの遠近の圧縮」は投影そのものから出てくるので、別途の押しつぶし hack は要らない。スプライト影(2c)も構造物影(2d)も、この一つの太陽から各自の投影を換算するので、向きは自然に一致し、長さは各自の高さの分だけ違う——物理的に正しい。

スプライト影は足元にアンカーする:現フレームを一度走査して最下段の不透明ピクセル行を支点として見つけ(キャッシュ)、その行を固定し、上の行を `lean` に沿って反太陽方向へ傾ける。こうして影は足の接地点からちょうど生え、浮かない。

### かすめる太陽がスプライト影を一本の線につぶす

スプライト影は現フレームに一度 2D アフィンシアーをかけたものだ。シアー基底の y 軸 `lean` の画面垂直成分 `lean.y` は、太陽方向を画面に投影した垂直成分に比例する。太陽が画面の水平方向をかすめるとき——セル空間で `sun_cell.x + sun_cell.y → 0`——この垂直成分は 0 に近づき、シアー行列

```text
[ 1    lean.x ]
[ 0    lean.y ]   行列式 = lean.y → 0
```

は退化する:スプライト全体が足元の 1px の横線につぶれる。

構造物影(2d)は本物のシルエットレイマーチなのでつぶれない;つぶれるのはスプライトのアフィンシアーだけだ。直し方は 2c にだけ二つの下限・上限を入れること:`lean.y` の絶対値に下限(信じられる厚みを残し、わずかに前下方へ落ちることを強制)、slope に上限(極端に低い太陽でも長さが発散しない)。静的な既定の太陽はかすめる領域に入らないので、この二つのクランプは発動せず、元の影はピクセル単位で変わらない。

![シアー行列のつぶれ vs つぶれ防止クランプ](https://code.leafvmaple.com/assets/hd2d/shadow_collapse.png)

このつぶれはむしろスクリーンショットに撮れない——かすめる時につぶれた影は足元の横線で、ちょうどキャラクターの体に隠れ、夕暮れの暗い草地ではコントラストもゼロ。メカニズム的な問題は、ゲーム画面より幾何の概念図のほうが明快だ。通常の太陽下でのスプライト投影はこうなる:

![キャラクター投影 オフ vs オン](https://code.leafvmaple.com/assets/hd2d/char_shadow.png)

### 構造物影は本物のレイマーチ、つぶれない

壁・建物・木といったタイルはアフィンシアーを通さない:まずそれらをひとつのシルエットテクスチャに描き、地面の shader が光の向きに沿って段階的にレイマーチしてそのシルエットをサンプリングし、連続した硬い影を落とす。利点は、連なった建物がバラバラに影を落として団子状に潰れないこと、木は木の形の影を落とすこと。本物のシルエット投影なので、かすめる時はただ伸びるだけで退化しない——行列式がゼロに近づく問題がない。だからつぶれ防止クランプはスプライト影(2c)にだけ入れ、構造物影(2d)には要らない。

構造物影はこの中で最も面積が広く、最も一目で分かる層だ——オフにすると地面が一気に平らで明るくなる:

![構造物投影 オフ vs オン](https://code.leafvmaple.com/assets/hd2d/struct_shadow.png)

### 接触 AO がキャラクターを地に着かせる

方向投影は太陽が高いとき、あるいは向きがかすめて薄くなるときにほぼ消える。すると人物が浮いて見えやすい。そこに接触 AO をもう一枚重ねる:足元に常駐する柔らかな暗い楕円(二乗減衰のソフトコア、地面に貼り付くよう縦に潰した比率、z は最下層)。光の向きには依存せず、ただ人や物を地面に押さえつける。方向影が「光がどこから来るか」を、接触 AO が「確かに地に立っている」を担い、役割を分ける。

## 三、2D 動的ライティング:環境光、点光源、法線

ライティングは二層の重ね合わせだ。下層は一枚の `CanvasModulate` 環境光で、キャンバス全体に時刻で変わる色を掛ける——昼は白に近く、夜は寒色の青寄り。それ自体は発光せず、「光源がないとき世界がどれだけ明るく、何色か」を定義するだけ。上層は `PointLight2D` の点光源(提灯、松明、主人公の携行光)で、環境光の上に局所を明るくする。

`PointLight2D` に `normal_map` を付けると、点光源が本物の陰影の起伏を照らし出せる:提灯・松明・月光が壁や地面に「まとわりつく」。タイルに法線マップを一枚ベイクして付ければよい。

ところがその直後、主人公の足元の松明の光だまりがそのまま**半減する**。原因は自動生成された法線にある:平均法線は光を正面に向いておらず、`N·L < 1` となるため、法線で変調された地面の、同じ一灯に対する平均応答は、素の平面より暗くなる。壁には起伏があり法線を付ける価値がある;地面はもともと平らで、法線を付けても明るさを無駄に食うだけだ。直し方は Building/Overhead 層にだけ法線を付け、Floor 層は素の平面のままにすること。

![動的ライティング: 暗い環境光 + 暖色点光源](https://code.leafvmaple.com/assets/hd2d/lighting.png)

携行光はさらに、環境の明るさで**暗さによるゲート**をかける:毎フレーム現在の環境光から明度を見積もり、明るいほど消し、暗いほど点ける——昼は消え、夕暮れに立ち上がり、夜に満ちる。松明は点くべきときだけ点り、真昼に顔や地面を白飛びさせず、夜には唯一の光源になれる。光源が「いつ意味を持つか」もデータ化され、常時点灯ではない。

## 四、カスタムマテリアルがスプライトを約1割暗くする——同じ穴に三度落ちた

HD-2D の看板であるリムライト:キャラクターの背後に寒色の青い縁取りを一筋入れ、人物を背景から切り出す。最初の版では rim マテリアルをスプライトの本体ノードに直接付けた。結果、キャラクター全体が周囲より一段暗くなった。

実測:同一スプライトで、任意のカスタム `ShaderMaterial` を付けるとサンプリング輝度が 55.2 → 49.5、**約1割暗くなる**。`render_mode unshaded` でも解決しない——これは「ライティングのかかったキャンバスでマテリアルを持っている」こと自体から来る。gl_compatibility の 2D ライティングパイプラインの癖だ。

直し方は、rim を本体スプライトから外し、**加算合成の複製スプライト**に変えること:現フレームを複製し、rim マテリアルを付け、`blend_add`、高い `z_index` を与える。本体スプライトはもうマテリアルを持たず、暗くされない;そしてその高 z の重ねレイヤーには思わぬ利点がある——**木の上に描かれる**ので、木陰に隠れた NPC まで縁取りで浮かび上がらせる:

![リムライト オフ vs オン](https://code.leafvmaple.com/assets/hd2d/rim.png)

同じ癖にこの後さらに二度落ちた:

- **キャラクターのシネマティックグレーディング**(`char_grade`、ガンマ/コントラスト/彩度):マテリアルファクトリは三項すべてが 1.0 のとき「恒等マテリアルを付ける」のではなく `null` を返す。マテリアルが付いている限りあの1割の暗さは残るからだ——値を 1.0 にしても「消えきっていない」ように見えるのはこれが理由。本当のスイッチは `null` だ。
- **スプライトの明度上げ**(`char_brightness`):`self_modulate` はカスタムマテリアル付きのスプライトには効かない。そこで二経路に分ける——グレーディングがオフのときはマテリアルなしで `self_modulate` により素直に単調に明るくし;オンのときはグレーディング shader 内の `grade_brightness` が担う。二つは等価。

![キャラクターグレーディング: ガンマで中間調を暗く + コントラスト + 彩度](https://code.leafvmaple.com/assets/hd2d/char_grade.png)

## 五、時刻、フォグ、大気と草木

時刻(0〜24 時)で変化するキーフレームテーブルが、カラー調整 + フォグ + 太陽をまとめて駆動する。既定ではポストプロセスのカラーとフォグだけを動かし、調整済みの影の向きには決して触れない;`daynight_sun` を明示的にオンにしたときだけ、太陽(影)が時刻に追従する——アイソメトリックでは太陽が上半球にいなければ、影が手前下方に落ちて見えないからだ。シナリオイベントは `set_time_of_day("dusk", 2.0)` のようなインタフェースで時刻を滑らかに切り替える。

![夜へ: カラー + フォグ + 太陽がまとめて寒色・暗めに](https://code.leafvmaple.com/assets/hd2d/night.png)

フォグは二種類、互いに補完する:**距離フォグ**は画面の Y に沿って上ほど濃くなり(アイソメトリックでは上ほど遠い)、遠景を抑える;**地表の寒色フォグ**は SubViewport 内の FBM ノイズ層で、下方の前景を抑え、夜ほど濃く、昼は 0 まで消える。上と下で奥行きを出す。

![二つの補完的なフォグ:上=距離フォグで遠景、下=地表フォグで近景](https://code.leafvmaple.com/assets/hd2d/two_fog.png)

大気パーティクル(舞う塵/落ち葉/雪/雨/火の粉/花びら)は SubViewport 内に置かれ、同じカラー調整とブルームを受けるので、夜に唐突に浮かない。パーティクルとレンズのガラスに当たる落ち葉は動的で、静止画では分からないので動画を:

![スクリーンエフェクト: 大気の落ち葉 + レンズの落ち葉(動画)](https://code.leafvmaple.com/assets/hd2d/screenfx.gif)

植生にはさらに頂点シェーダによる風揺れが一層ある。肝心なのは株ごと平行移動させないこと——それでは揺れではなく滑りに見える。`TileMapLayer` の UV はアトラスの正規化座標で、木のタイル一種ごとにアトラス内の固定した縦区間を占める;各木タイルの不透明ピクセルを走査し、[区間の上端、下端、有効下端の割合] を shader に詰める。頂点は自分がどの区間に落ちるかからタイル内の縦位置を求め、**有効下端(幹の根元)より下は固定し、梢の先端へ向けて線形に最大振幅まで増やす**(二乗で幹を硬く、梢を柔らかく)。幹は安定し、梢だけが揺れ、隣り合う木は世界座標で位相をずらすので、一面が同期して揺れない。

![草木の風揺れ: 梢だけ揺れ、幹は固定(動画)](https://code.leafvmaple.com/assets/hd2d/wind.gif)

ティルトシフトは今のところ画面 Y で帯状に分ける「偽」のぼかしだ(下図はオン/オフ比較、ぼかし量を見やすく少し強めた)。真の被写界深度はセルの奥行きを深度として駆動する必要があり、後回しにしている:

![ティルトシフト オフ vs オン](https://code.leafvmaple.com/assets/hd2d/dof.png)

## 六、これらをオフにできるトグルにする

エフェクトが積み上がるほど、項目ごとにオフにできる必要がある。最終的に全部を一つのトグルシステムに繋ぐ。三グループ——シーン(ライティング/風揺れ/パーティクル/地表フォグ/レンズの落ち葉)、ポストプロセス(ブルーム/被写界深度/ビネット/色収差/グレイン/距離フォグ/LUT)、キャラクター(投影/リムライト/グレーディング)——既定で全オン、即時反映、シーンの再構築なし。

実装はエフェクトの持ち主ごとに分ける:ポストプロセス系は対応する uniform を設定値か中立の 0 に押し込む(距離フォグは時刻に駆動されるため、時刻が変わるたびに gate を掛け直す);キャラクター系は子ノードの表示/非表示やグレーディングマテリアルを切り替える;シーン系はライティングの可視性切り替えや子ノードの追加・削除を行う。距離フォグのように時刻に毎フレーム上書きされるものは、gate を時刻適用の後に置かなければ、また上書きで戻されてしまう。

## 七、ここからどこへ行けるか

ここまでの一山は「現行パイプラインで ROI が最も高い層」だ——その大半は画面空間の安価な近似で、真の幾何はなく、立体感はすべて 2D の上でこしらえている。さらに上は二つの段に分かれる。

### 発展:現行パイプラインで拡張できるもの

- **ボリュメトリックライト / ゴッドレイ**:画面空間の放射状ブラーを光源から外へ発散させ、木漏れ日や窓格子から差す光の柱を作る。純粋なポストプロセスでアートアセットに触れず、雰囲気への効果が大きい。参考:Ori and the Blind Forest、Hollow Knight。
- **水面の反射 + 屈折**:世界を水面に対して鏡像でもう一度レンダリングして反射とし、法線の揺らぎを重ねて屈折とする。武侠の舞台は水が多く、効果が直接的。参考:Sea of Stars、Eastward。
- **多層パララックス + 前景ぼかし**:遠景を層ごとに視差移動させ、前景の枝や草をぼかして半透明でレンズを遮ると、奥行きが一気に出る。
- **真の被写界深度**:今のティルトシフトは画面 Y で帯状に分ける偽のぼかし;アイソメトリックなシーンは本来「セルの奥行き」を持つので、それを深度マップとして錯乱円(CoC)を駆動するのが、幾何的に正しい被写界深度だ。これは「偽 → 真」で最も埋めるべき穴。

### 最前線:ライティングの土台を入れ替えるもの

- **Radiance Cascades**:2023–24 に現れた 2D リアルタイムグローバルイルミネーション(Alexander Sannikov、Path of Exile 2 で使用)。要は画面上に多段の「放射輝度カスケード」プローブを敷く——遠方は角度分解能を高く・空間密度を低く、近傍は逆に——ソフトシャドウ、色のにじみ(紅葉が暖色を地面や人物に映す)、そして本物の間接光を合成する。現状の 2D 画質の天井であり、コミュニティに Godot 実装も既にある。
- **SDF + Jump-Flood レイマーチ**:シーンを符号付き距離場にベイクし(jump-flooding で高速生成)、ray-march でソフトシャドウと局所ライティングを出す。Radiance Cascades の軽量な前身であり、ボリュメトリックライト・水面・動的ソフトシャドウが共用できる統一の土台でもある。
- **拡散モデルによるオフラインの画像補強 / スタイル変換**:生成モデルで手描きや仮アートのスタイルを統一し、法線マップと高さマップを補って、上のライティングパイプラインに供給する。「アート制作能力」という本当のボトルネックをパイプラインから解き放つ。

### 一本の軸

これらのトレードオフの背後にあるのは同じ一つのことだ:**2D には真の幾何も深度もなく、立体感はすべて画面空間で近似と引き換えに得ている**。上へ行くほど、本来 3D に属するもの——グローバルイルミネーション、距離場、深度——を、許容できるコストで 2D に持ち込む営みになる。現行パイプラインは「安価な近似」の層に留まっている:法線が偽の起伏を、シアーが偽の投影を、ティルトシフトが偽の被写界深度を、層分けが偽の奥行きを与えた。どの「偽」も、真値に置き換えられるのを待つ穴だ。Radiance Cascades が天井であるのは、2D の間接光をリアルタイムで賄えるほど安くした初めての手法だから——「ライティング」という一項を、近似から本当に計算へ置き換えた。
